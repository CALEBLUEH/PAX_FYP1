## Persistence contract

- New captures/writes use XML **version 2**. Each placed cell carries a stable `material` ID. Removed cells remain coordinates only. No file paths, shader/type names, scene references or arbitrary asset loading enter the save format.
- XML **version 1** is still read strictly. Its untyped placements mean `default` (the original prefab Grass); loading then saving captures version 2, and the compatible version 1 primary can become the recoverable backup. The real old-format fixture is `Assets/PAX/Tests/Fixtures/LegacyTileEditsV1.xml`.
- Older compiled players cannot read version 2. Backward compatibility here means the updated code reads version 1 and preserves recoverable old backups, not that older binaries understand new material data. No slot is automatically imported or overwritten on startup.
- The authored-world fingerprint algorithm is unchanged and excludes palette/selection/UI. The new scene's tile baseline matches the original expedition. Legacy expedition edits can therefore be validated against this scene; normal slots remain separate. Old default-only scenes read/write default v2 and reject IDs they cannot resolve.
- The codec rejects unsupported versions, malformed/duplicate cell data, missing/unknown attributes, invalid ID syntax, orphan metadata, DTDs and excessive data. The world resolves every placement's ID against its assigned catalog before changing any renderer, collider, list or revision. Wrong-world/protected-removal/body-overlap rules remain in force.
- Exact materials, mineability, colliders and independent shadow children are restored from validated target state. Mixed-material replacement is a semantic edit; replacing an authored tile with its original material remains no delta. Unknown placed material references refuse saving rather than losing information.
- Atomic temporary-file/replace behavior and compatibility-aware backups remain. Corrupt/incompatible primary data is archived separately instead of replacing a valid `.bak`. The gameplay save service always supplies world/palette validation before file mutation. The low-level writer refuses non-default IDs without a validator, and never promotes an unverifiable typed primary over a valid backup. No autosave or destructive migration is added.
- Selected hotkey and survey journal are session state. Saves store tile edits/materials only. Objective repair progress still follows actual solid cells, regardless of material; no inventory, economy, reward or quest-schema expansion.
