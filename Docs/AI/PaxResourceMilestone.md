## Snapshot and accounting contract

- Finite F5/F9/F8 use a distinct `<pax-resources version="1">` envelope containing typed v2 tile edits, all stock counts and harvested-cell history. This is one atomic file, never separate inventory and tile saves. Old tile-only v1/v2 files are explicitly rejected in finite mode; unlimited modes retain their existing support.
- Compatibility includes the authored-world fingerprint and a SHA256 signature over sorted stable IDs/material names, start counts, authored yields, limits and fixed cost/refund rules. Unsupported/stale formats, unknown/duplicate IDs, missing sections, negatives, overflow, excessive data, protected/unknown harvests and wrong worlds reject before either live state changes.
- Validation reconstructs expected stocks from starts + once-only authored harvest yields - units tied up in current rebuilt/new tiles, and requires exact equality with saved counts. A forged count or tile-only rollback cannot mint units. Identical-material rebuilds are charged using the ledger even when the tile delta is empty. Counts use bounded ints; conservation arithmetic uses longs.
- Loading validates the complete resource state first, then the existing world/body-safety validation completes before tile mutation. Only after successful tile application are stocks/ledger replaced with the validated absolute snapshot. Repeated loads do not add rewards or accumulate units. Survey visits/activation remain session-only; repairs still derive from current solids.
- Both formats share `PaxAtomicFile`: validated content, bounded read, same-directory flushed temporary file, atomic replacement, compatible primary → `.bak`; corrupt/incompatible primary → separate `.invalid-*` while the valid backup is kept. No autosave, destructive import or silent tile-only fallback.
- Direct unaccounted debug world edits fail conservation on save; normal player edits go through `PaxBuilder`. This is a local consistency contract, not encrypted anti-cheat or recovery from engine/process failure during in-memory instantiation.
