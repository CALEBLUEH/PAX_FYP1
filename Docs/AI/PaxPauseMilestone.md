# Finite expedition pause and controls

18 October 2026, trip rotation 6, isolated `CodexWorkspace` from `3d0470c`. One usability/input milestone in the existing finite Resource Expedition and Lowtide Chart scenes. Their terrain, markers, compositions, save slots and resource rules remain in place. No new episode or menu.

## Player behavior and authoring

**Escape** opens the authored controls overlay and pauses; another fresh Escape press or the **Resume** button resumes. Focus loss pauses automatically. Returning focus never resumes automatically, and an Escape already held during refocus is ignored until released and pressed again. Resume requires all held keys/mouse buttons to be released before a fresh gameplay action; the release frame itself is consumed. The UI button's click therefore cannot also mine/place in the world.

The overlay explains movement/jump/rescue, camera orbit/tilt/zoom/reset, smart/precise targeting and side-face bridge building, material selection and exact refunds, F5 combined stock/tile save, F9 current load, F8 previous recovery, and F6 session-only discovery restart. Scene-specific Inspector text describes beacon activation versus chart recovery. Pausing never saves, reloads, resets the journal, refills supplies or moves the player.

`PaxPause` is saved on each finite scene's existing Authored HUD object. Its document, player, builder, pause key, title/focus strings and mission help are editable. Eight relevant components have explicit optional owner references: input, player, camera, builder, expedition/input, palette and save facade. Empty references keep the four earlier unlimited scenes opted out. `PaxPauseAuthoring.EnsurePause` wires only the two finite scenes and adds one shared `PauseHelp.uxml` template instance to their separate existing UXML assets. Repeating authoring preserves existing custom help/layout and does not duplicate objects/buttons. Required assignments are saved; no package or external asset is needed.

## State and input contract

- The scene pause owner retains the previous time scale and restores that exact value on resume, disable or scene unload. Player and camera updates explicitly skip pause, preserving mid-jump velocity and camera transforms instead of processing a zero-duration jump-release tick. Discovery observation also skips pause so partial dwell neither advances nor resets. Rendering/HUD presentation can continue on unscaled time.
- Opening/resuming clears pending movement/jump presses and queued mine/place actions. `PaxInput` samples raw hardware into `PaxInputFrame` and applies it through the same guarded dispatch used by validation. Palette and mission key readers also check the owner before dispatch.
- Public player rescue/command, camera orbit/zoom/reset, builder mine/place/tool/palette, mission activation/restart and save/load facade methods reject while paused or awaiting release. The world codec/resource accounting layer remains unchanged; raw debug world mutation APIs are not a player input path.
- UI callbacks are removed on disable and bound once when the document is ready. The overlay fills the panel and contains a real UI Toolkit Button. Clock ownership and command queues are released on disable/unload. Scene reload does not carry a static paused state.
- `UseValidationInput` is restricted to the Editor or explicit `-paxSmoke` players. It bypasses hardware sampling/focus callbacks only for deterministic transition fixtures. Normal players sample actual Escape, held state and focus callbacks.
